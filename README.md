# SelfCRMlanding

Статичный лендинг SelfCRM: https://doc9830.github.io/SelfCRMlanding/

Страница рассказывает про текущую версию приложения: сейчас это **1.5.0** (позиционирование: SelfCRM — **личная CRM**; в 1.5.0 к складу добавились **массовый приход и списание** — окно с причинами и количествами, причина попадает в движение каждой позиции; кнопка «Повторить заказ» из 1.4.0 и «личная CRM» из 1.4.1 остались). При выпуске новой версии обновляются номер и ссылка на APK в `<head>` (meta, JSON-LD), кнопка в hero, подпись «Версия … · Android · APK …», шаг 01 в «Установке», скриншоты и строка версии на `og-cover.png`.

## Что внутри

- `index.html` — единственная страница: hero с живым демо экранов, галерея кадров, возможности, «бесплатно», поддержка, установка. Тема (светлая/тёмная) переключается кнопкой в шапке и запоминается в `localStorage` (`selfcrm-landing-theme`); от неё зависят и кадры приложения.
  - Hero собран так, чтобы в первый экран ноутбука влезали кадр приложения, кнопки-табы под ним и кнопка перехода: `--phone-w: clamp(238px, calc((100dvh - 320px) * .4621 + 22px), 372px)`, где 22 px — рамка вокруг кадра, а `.4621 = 390 / 844` — соотношение сторон снимка. На `min-height: 1000px` кадр растёт до 414 px, при ширине ≤ 1020 px — до 342 px. Проверено на 1440×900 (кадр 290 px) и 1366×768 (238 px): кадр и демо целиком выше сгиба.
  - Клик по кадру в hero или по карточке галереи открывает снимок в лайтбоксе (до 660 px в ширину, без апскейла); закрывается по Esc, клику по фону и по крестику.
  - Галерея: 20 кадров, фильтры «Все / Клиенты и заказы / Товары и склад / Главная, отчёты и настройки», кадры грузятся лениво и меняются вместе с темой сайта. Сетка — `repeat(auto-fill,minmax(188px,1fr))` с `gap:14px`, а с 1021px `minmax(248px,1fr)`: на ноутбуке и десктопе 4 кадра в ряд (кадр 226px), на телефоне один в ряд (318px), планшет — 3 в ряд. Карточки строятся скриптом через `<figure>`, поэтому в сбросе стоит `figure{margin:0}` — браузерные поля `1em 40px` съедали по 80px ширины карточки, и кадр внутри выходил вдвое мельче.
  - Живое демо hero: табы листают маршруты приложения (объект `SCREENS` в скрипте), кнопка действия ведёт на следующий экран, «Назад» возвращает по стеку, справа показывается описание текущего экрана. Цепочка склада: «Склад» → «Массовый приход» → «Массовое списание» → «Движение товара» → «Изменение остатка».
- `Screenshots v3/` — 20 экранов приложения в двух темах, 40 PNG (780×1688, DPR 2, PNG8, ~2,1 МБ). Имена файлов: `Экран (светлый|темный).png`. Кадры сняты с версии 1.5.0 при окне 390×844.
- `og-cover.png` — обложка 1200×630 для соцсетей и мессенджеров (`og:image`): вертикальный градиент, крупная надпись, телефон с кадром главного экрана и строка версии. Телефон: 270×560 в точке 883×35, внешнее скругление 26, кадр 250×540 со скруглением 17 (DejaVu Sans, светлая строка #93C5FD). Обложка собирается скриптом: `python3 make-cover.py --version 1.5.0 --shot "<кадр главного экрана>" --out og-cover.png` (нужен Pillow) — тот же файл уходит на обложку релиза в репозитории приложения (`release-assets/<тег>/cover.png`).

## Как обновить скриншоты

Кадры снимаются прямо из приложения (репозиторий [SelfCRM](https://github.com/doc9830/SelfCRM)) через headless Chrome:

1. Собрать и поднять preview: `npm run build`, затем `npm run preview -- --port 4173 --strictPort`.
2. Запустить Chrome с отладочным портом: `google-chrome --headless=new --remote-debugging-port=9222 --user-data-dir=/tmp/chrome-shots --window-size=390,844`.
3. Поставить шрифт Roboto (`~/.fonts/roboto`) — кадры выходят с андроидным текстом.
4. Снять обе темы: `node /tmp/selfcrm-shots/shots.mjs --theme=light --out=/tmp/selfcrm-shots/light` и то же с `--theme=dark`. Скрипт сам пишет демо-базу в `localStorage['selfcrm:data']` (подрядчик, 8 клиентов, 14 товаров и услуг, 14 заказов со статусами, оплатами и напоминаниями, движения склада), дальше открывает каждый маршрут отдельной загрузкой страницы (иначе приложение остаётся с прежней базой в памяти), блокирует запросы к `api.github.com` и `suggestions.dadata.ru`, проверяет, что нужные тексты есть на экране (`must`), и складывает текст каждого экрана в `texts.txt` рядом со снимками. Экраны (20): главный, клиенты, карточка клиента, архив клиентов, новый клиент, заказы, заказ в работе, новый заказ, завершённый заказ, повтор заказа, товары, карточка товара, склад, массовый приход, массовое списание, движение товара, изменение остатка, низкий остаток, статистика, настройки. Массовые операции снимаются не отдельным маршрутом, а действием: `fillBulkForm()` нажимает кнопку на экране склада и заполняет причину с количествами в открывшемся окне.
5. Оптимизировать: PNG8 (`quantize(256, Image.MEDIANCUT)`, `optimize=True`), размер оставить 780×1688 — это ровно 390×844 при DPR 2.
6. Положить файлы в `Screenshots v3/` — имена должны совпадать с полем `file` в объекте `SCREENS` (`index.html`), иначе галерея и демо не найдут кадр.
7. Пересобрать обложку: `python3 make-cover.py --version <версия> --shot "<кадр главного экрана>" --out og-cover.png` (геометрия и тексты — в самом скрипте), и обновить номер версии в текстах страницы.
